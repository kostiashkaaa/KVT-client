# Архитектура KVT

## Процессы и привилегии

```
KVT.exe (обычные права)
├─ UI (Tauri/WebView2, выгружается в трей)
└─ kvt-core (Rust)
   ├─ подписки → модель → RoutingPlan → компилятор: Xray JSON | sing-box JSON | zapret2
   ├─ NetGovernor — все сетевые запросы приложения идут только через него
   ├─ тестер серверов, DNS-check, диагностика, детектор заморозки
   └─ HTTP: системный Schannel (отпечаток как у Windows/Edge), DoH
                 │ named pipe \\.\pipe\kvt-service (ACL + проверка подписи)
KVTService (SYSTEM, тонкая)
├─ запускает одно ядро с собственным TUN: xray.exe или sing-box.exe
├─ winws2.exe (zapret2) — в режимах Zapret/Гибрид
└─ WFP: kill switch, запрет DNS мимо туннеля, IPv6, восстановление
```

Правила:

1. Недоверенные данные разбираются только в процессе без прав.
2. Служба не принимает путей, аргументов и сырых конфигов — только `ipc::Request`.
3. Секреты не попадают в argv, логи, WebView и аварийные дампы (`Secret`).
4. Локальных inbound в режиме TUN нет. Если порт неизбежен — пароль, случайный
   порт и WFP-фильтр по процессу.

## Ядра

| Возможность | Ядро |
|---|---|
| XHTTP, Finalmask, VLESS Encryption | только Xray |
| VLESS/REALITY/Vision, Trojan | Xray (по умолчанию) |
| Hysteria2, Shadowsocks, TUIC, AnyTLS, Naive | sing-box |

Оба ядра поднимают собственный TUN — цепочек через локальный SOCKS нет.
Выбор — `kvt_core::core_select::select_core`.

## RoutingPlan

Единый источник правды. Слои по приоритету: System (LAN, адреса серверов) → User →
Zapret → Preset (Россия) → Provider (выключен по умолчанию) → final.

Инварианты (`RoutingPlan::validate`, покрыты тестами):

- адрес VPN-сервера никогда не попадает под zapret и всегда в `--ipset-exclude`;
- правила подписки не могут включать zapret;
- zapret задаётся только доменами (hostlist).

## NetGovernor

Наблюдения сообщества (2026): ТСПУ замораживает узел примерно на 120 с, если к одному
SNI открыто больше ~3 TLS-соединений за короткое время; поток к подозрительным
подсетям замирает после ~16–20 КБ. Пороги не подтверждены официально и меняются,
поэтому хранятся как данные (`presets/net-policy.json`).

Политика по умолчанию: не больше 2 новых TLS на SNI за 60 с, пауза 2 с, после
заморозки — 180 с тишины, отпечаток не меняется.

## Проверка серверов

1. Статическая проверка (парсер).
2. DNS.
3. TCP/QUIC-доступность.
4. Рукопожатие через тестовое ядро без inbound.
5. Скачивание ~200 КБ.

Вердикт — `probe::classify`: работает / медленно / DNS / недоступен / заморозка
TLS / заморозка данных.

## Kill switch

Фильтры WFP в динамической сессии службы (`kvt-service/src/wfp.rs`). Разрешены: loopback,
интерфейс TUN, процессы ядра и службы, локальная сеть и DHCP; остальное блокируется на
уровнях ALE_AUTH_CONNECT v4/v6. Блокировка держится и после падения ядра — до «Отключить».
При падении или остановке службы Windows удаляет фильтры сама, поэтому KVT не может
оставить компьютер без интернета.

## Проверка утечек

`app/src-tauri/src/diagnostics.rs`: открытые SOCKS5 без пароля на локальных портах
(netstat + SOCKS5-приветствие), исходный адрес для IPv4/IPv6 (UDP connect без отправки
пакетов), резолвер через `whoami.akamai.net` — единственный сетевой запрос.

## Этапы

1. ✅ kvt-core: подписки по сети, компиляторы конфигов, тестер с эмулятором ТСПУ.
2. ✅ Служба: ядра с TUN, списки podkop/runetfreedom, WFP kill switch, DACL на pipe,
   проверка клиента, проверка утечек, трей.
3. DNS-check и «Почему не работает?», профили сетей.
4. zapret2: гибрид и автоподбор стратегий.
5. Миграция из других клиентов, журнал сетевых запросов, аудит ПК, подпись, автообновление.
