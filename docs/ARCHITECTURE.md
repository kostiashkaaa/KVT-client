# Архитектура KVT

## Процессы и привилегии

```
KVT.exe (обычные права)
├─ UI (Tauri/WebView2, выгружается в трей)
└─ kvt-core (Rust)
   ├─ подписки → модель → RoutingPlan → компилятор: Xray JSON | sing-box JSON | zapret2
   ├─ NetGovernor — все сетевые запросы приложения идут только через него
   ├─ тестер серверов, DNS-check, диагностика, детектор заморозки
   └─ HTTP: системный Schannel (отпечаток как у Windows/Edge), DoH
                 │ named pipe \\.\pipe\kvt-service (ACL + проверка подписи)
KVTService (SYSTEM, тонкая)
├─ запускает одно ядро с собственным TUN: xray.exe или sing-box.exe
├─ winws.exe (zapret Flowseal) — в режимах Zapret/Гибрид
└─ WFP: kill switch, запрет DNS мимо туннеля, IPv6, восстановление
```

Правила:

1. Недоверенные данные разбираются только в процессе без прав.
2. Служба не принимает путей, аргументов и сырых конфигов — только `ipc::Request`.
3. Секреты не попадают в argv, логи, WebView и аварийные дампы (`Secret`).
4. Локальных inbound в режиме TUN нет. Если порт неизбежен — пароль, случайный
   порт и WFP-фильтр по процессу.

## Ядра

| Возможность | Ядро |
|---|---|
| XHTTP, Finalmask, VLESS Encryption | только Xray |
| VLESS/REALITY/Vision, Trojan | Xray (по умолчанию) |
| Hysteria2, Shadowsocks, TUIC, AnyTLS, Naive | sing-box |

Оба ядра поднимают собственный TUN — цепочек через локальный SOCKS нет.
Выбор — `kvt_core::core_select::select_core`.

## RoutingPlan

Единый источник правды. Слои по приоритету: System (LAN, адреса серверов) → User →
Zapret → Preset (Россия) → Provider (выключен по умолчанию) → final.

Инварианты (`RoutingPlan::validate`, покрыты тестами):

- адрес VPN-сервера никогда не попадает под zapret и всегда в `--ipset-exclude`;
- правила подписки не могут включать zapret;
- zapret задаётся только доменами (hostlist).

## NetGovernor

Наблюдения сообщества (2026): ТСПУ замораживает узел примерно на 120 с, если к одному
SNI открыто больше ~3 TLS-соединений за короткое время; поток к подозрительным
подсетям замирает после ~16–20 КБ. Пороги не подтверждены официально и меняются,
поэтому хранятся как данные (`presets/net-policy.json`).

Политика по умолчанию: не больше 2 новых TLS на SNI за 60 с, пауза 2 с, после
заморозки — 180 с тишины, отпечаток не меняется.

## Проверка серверов

1. Статическая проверка (парсер).
2. DNS.
3. TCP/QUIC-доступность.
4. Рукопожатие через тестовое ядро без inbound.
5. Скачивание ~200 КБ.

Вердикт — `probe::classify`: работает / медленно / DNS / недоступен / заморозка
TLS / заморозка данных.

## Kill switch

Фильтры WFP в динамической сессии службы (`kvt-service/src/wfp.rs`). Разрешены: loopback,
интерфейс TUN, процессы ядра и службы, локальная сеть и DHCP; остальное блокируется на
уровнях ALE_AUTH_CONNECT v4/v6. Блокировка держится и после падения ядра — до «Отключить».
При падении или остановке службы Windows удаляет фильтры сама, поэтому KVT не может
оставить компьютер без интернета.

## Проверка утечек

`app/src-tauri/src/diagnostics.rs`: открытые SOCKS5 без пароля на локальных портах
(netstat + SOCKS5-приветствие), исходный адрес для IPv4/IPv6 (UDP connect без отправки
пакетов), резолвер через `whoami.akamai.net` — единственный сетевой запрос.

## Проверка DNS

`kvt_core::dns` — данные и выводы, `app/src-tauri/src/dnscheck.rs` — запросы. Пять резолверов
(Яндекс, Cloudflare, Google, Quad9, AdGuard) по UDP, DoT и DoH; около 30 коротких запросов,
по одному TLS-соединению на резолвер, повтор в течение минуты отдаёт прошлый результат.

- **Перехват**: `whoami.akamai.net` возвращает адрес резолвера, который на самом деле спросил
  Akamai. Перехват засчитывается, только если его подтверждает второй признак: ответ совпал
  с резолвером сети или DoH того же провайдера выходит из его сетей.
- **Подмена**: facebook.com и rutracker.org на разной инфраструктуре. Один адрес для обоих,
  адрес из частной сети или «нет такого домена» при ответе DoH — заглушка провайдера.
  Адреса 198.18.0.0/15 — FakeIP роутера (podkop, sing-box), это не подмена.
- DNS в конфиге ядра (`DnsPlan`) принимается службой только из каталога резолверов.

## «Почему не работает?»

`app/src-tauri/src/troubleshoot.rs`: сбор фактов (сеть, служба, подписка, TCP-пинг сервера,
интернет без VPN, одна проба через тестовое ядро с лимитами NetGovernor или запрос через
туннель) и чистая функция `conclude` — первый найденный сбой, понятный вывод и действие
одной кнопкой (подключить, отключить, переключиться на рабочий сервер, обновить подписку).

## Профили сетей и автопереключение

- Сеть узнаётся по MAC-адресу шлюза адаптера с маршрутом по умолчанию (`netinfo.rs`, IpHelper,
  без сетевых запросов, раз в 10 с). Профиль: включать/выключать VPN и какой режим ставить.
  «Включено» — это и VPN, и режим «Zapret». Работающее подключение перезапускается, если профиль
  меняет режим, если включён «Гибрид» (winws привязан к прежнему интерфейсу) или если для новой
  сети подобрана другая стратегия zapret.
- Проверка туннеля — `http://www.cloudflare.com/cdn-cgi/trace` (меньше 200 байт, страна выхода).
  Системное правило `with_health_check` ведёт этот домен через VPN в любом режиме.
- Автопереключение (`watchdog.rs`): проверка раз в минуту по открытому соединению, сбой
  подтверждается ещё двумя попытками, замена — по итогам полной проверки, затем по TCP-пингу;
  не больше трёх переключений за 30 минут. Если ни одна замена не заработала, выбор и подключение
  возвращаются на прежний сервер.
- При переподключении с kill switch прежние фильтры WFP держатся, пока не встанут новые.

## Этапы

1. ✅ kvt-core: подписки по сети, компиляторы конфигов, тестер с эмулятором ТСПУ.
2. ✅ Служба: ядра с TUN, списки podkop/runetfreedom, WFP kill switch, DACL на pipe,
   проверка клиента, проверка утечек, трей.
3. ✅ Проверка DNS, «Почему не работает?», профили сетей, автопереключение сервера.
3.1. ✅ Удобство списка серверов (как в Happ):
   - **Единый список.** На главной все подписки и ручные ключи идут группами в одном
     прокручиваемом списке; сервер выбирается из любой группы, без «Сделать основной».
     У группы: название, трафик, срок, «Обновить», «Пинг», свернуть/развернуть
     (состояние запоминается). Поиск — по всем группам.
   - **Выбор по ключу, а не по индексу.** `Choice.server_index` → `{подписка, ключ сервера}`,
     ключ — хэш адреса, порта, протокола и идентификатора. Выбор переживает обновление
     и перестановку серверов в подписке. Перенос старого `server_index` при запуске.
     Итоги проверок, трей и автопереключение (сначала та же подписка, потом остальные)
     работают с ключами.
   - **Кнопка «+»** в заголовке списка и в разделе «Подписки»: панель добавления
     ссылки или ключа поверх текущего списка; буфер обмена читается только по кнопке.
     Ключи без ссылки собираются в одну группу «Добавлено вручную».
   - **Флаги и эмодзи.** Windows не рисует эмодзи-флаги (вместо 🇩🇰 видно «DK»), поэтому
     пары региональных индикаторов в названии заменяются на SVG-флаги из встроенного
     набора flag-icons (MIT, без сетевых запросов). Остальные эмодзи — цветным шрифтом
     Segoe UI Emoji. Флаг стоит слева от названия, сам символ из названия убирается.
4. ✅ zapret Flowseal: режимы «Гибрид» и «Zapret», стратегии как данные с белым списком
   флагов, исключение VPN-серверов, автоподбор стратегии для сети, поиск конфликтов.
5. Всё, что нужно до первого релиза: журнал, аудит, миграция, надёжность, установщик,
   обновления. Порядок: 5.3 → 5.4 → 5.5 → 5.6 → 5.7 → бета 0.9.

   Шаг закрыт, когда тесты и clippy зелёные, документация обновлена, сделан коммит и
   пользователь проверил вживую от администратора всё, что идёт через службу. Пока живой
   проверки не было, у шага стоит пометка «вживую не проверено».
   - ✅ **5.1 Журнал сетевых запросов.** *(вживую со службой не проверено)* Каждое
     соединение, которое открывает KVT или служба, записывается: время, кто (приложение /
     служба), зачем (подписка, проверка сервера, DNS, диагностика, zapret, списки,
     обновление), хост без пути и параметров, через что (напрямую / туннель / тестовое
     ядро), итог и длительность. Отказы NetGovernor тоже видны («отложено», «заморожено»).
     Только в памяти, последние 500 записей, на диск не пишется. Служба отдаёт свою часть
     по IPC. Раздел «Журнал»: сводка по хостам за час (соединения, пик в минуту,
     отложенные) и список запросов с фильтром — видно, что всплесков нет.
   - ✅ **5.2 Аудит ПК.** *(исправления через службу вживую не проверены)* Утечки мимо VPN
     (прокси WinINet/WinHTTP от других клиентов, IPv6 и Teredo, вручную прописанный DNS,
     DoH в браузерах), конфликтующий софт (другие VPN, адаптеры TAP/Wintun, драйверы
     WinDivert/GoodbyeDPI, антивирусы с перехватом HTTPS), остатки zapret (чужие службы
     winws/GoodbyeDPI, автозапуск .bat). Отчёт с кнопкой «Исправить» у каждого пункта;
     сам аудит ничего не меняет.
   - ✅ **5.3 Миграция.** *(на настоящих v2rayN, Throne, NekoRay и Hiddify не проверено — по исходникам и тестовым базам)* v2rayN, Happ, Hiddify, NekoRay / Throne: поиск в стандартных
     местах и «Указать папку». Данные чужих клиентов только читаются; переносятся
     подписки (по ссылке) и ключи, с предпросмотром перед импортом.
     Серверы из подписок не копируются — переносится сама подписка; если она сейчас не
     загружается, ссылка сохраняется и обновится позже. Базы SQLite читаются из копии.
     Happ хранит подписки зашифрованными — KVT только подсказывает скопировать ссылку.
     - **Как читать.** v2rayN 6+, Throne, Hiddify и Happ хранят данные в SQLite — база
       копируется, читается копия, так что работающий клиент не страдает. NekoRay и
       старый Throne — JSON в `config/profiles`. Записи превращаются в обычные ссылки и
       проходят тот же разбор, что и подписка; у каждого формата — тесты на образцах
       без настоящих ключей.
     - **Куда.** Подписки по ссылке — обычными группами, ссылки сразу шифруются DPAPI;
       серверы подписок по одному не переносятся — KVT загрузит их сам. Дубликаты (та же
       ссылка или тот же ключ сервера) пропускаются и видны в предпросмотре.
     - **Проверить перед закрытием шага:** что видит пользователь, если клиент найден, но
       база заблокирована или в неизвестном формате (понятное сообщение, а не пустой
       список).
   - **5.4 Надёжность и понятные сообщения.** Чинит то, что сломает первый релиз, и даёт
     журнал, без которого не отладить установщик на чистых машинах.
     - **Журнал ошибок на диске.** Приложение и служба пишут события и ошибки в свои
       каталоги данных (служба — `C:\ProgramData\KVT\logs`): ротация 2 × 1 МБ, без
       секретов (`Secret`, хосты без путей), паника тоже попадает в журнал. Сейчас служба
       пишет в `eprintln!`, а у службы Windows этот вывод никуда не идёт.
     - **Экспорт диагностики** (перенесён из этапа 6 — нужен уже первым пользователям).
       Кнопка в «Почему не работает?» и на вкладке Zapret: архив с итогами проверок,
       журналами и сгенерированными конфигами, где ключи, пароли, UUID и URL подписок
       скрыты. Перед сохранением показывается, что войдёт.
     - **Настройки не теряются.** У `settings.json` — версия схемы и переносы между
       версиями. Нечитаемый файл сохраняется рядом как `settings.bad.json`, пользователь
       видит сообщение. Сейчас `unwrap_or_default()` молча сбрасывает kill switch,
       профили сетей и настройки zapret.
     - **Тексты ошибок.** Технические сообщения (ошибки reqwest и ввода-вывода на
       английском, «внутренняя ошибка состояния», «Неожиданный ответ службы», команда
       `kvt-service --console`) заменяются понятными, с действием; исходный текст — в
       журнал.
     - **Сон и пробуждение.** После выхода из сна (`PBT_APMRESUMEAUTOMATIC`) — сразу
       проверка туннеля и переподключение, а не через минуту автопереключения. Проверить
       Wintun после гибернации и после быстрого запуска Windows.
     - **Сеть со страницей входа (отель, кафе) и kill switch.** По проверке Windows (NCSI)
       понять, что сеть просит войти, и показать «Сеть просит войти — отключите VPN на
       время входа» с кнопкой. Иначе kill switch не даёт открыть страницу входа, и
       кажется, что сломан KVT.
     - **Удаление подписки при подключении.** Если удалён сервер, к которому подключены, —
       отключиться и сказать об этом. Сейчас KVT молча переподключается к первому серверу
       другой подписки.
     - **Загрузки с GitHub.** Списки, версия Flowseal, а позже и обновления берутся с
       `api.github.com` и `raw.githubusercontent.com`, которые у части провайдеров
       тормозят. Если напрямую не вышло, а VPN подключён — повтор через туннель, с теми же
       лимитами NetGovernor и записью в журнал.
   - **5.5 Установщик и подпись.** NSIS: KVT, служба, ядра, Wintun и комплект zapret в
     Program Files, регистрация службы. Удаление останавливает службу, снимает фильтры
     WFP и удаляет драйвер WinDivert. Подпись — шаг signtool в сборке, включается, когда
     есть сертификат; до этого служба проверяет клиента по пути и SHA-256 из манифеста
     установки, с подписью — ещё WinVerifyTrust и совпадение издателя.
     - **Служба запускается сама.** Сейчас она `OnDemand`, а приложение её не запускает,
       поэтому после перезагрузки KVT не подключится. Тип запуска — «Автоматически
       (отложенный запуск)»; при сбое — перезапуск (до трёх раз); пользователям выдаётся
       право `SERVICE_START`, чтобы окно могло поднять остановленную службу без прав
       администратора.
     - **Первый запуск и «служба не отвечает».** Вместо ошибки на главной — объяснение и
       кнопка «Запустить службу».
     - **WebView2.** Загрузчик Evergreen в NSIS; отдельный офлайн-установщик со
       встроенным WebView2 для компьютеров без интернета.
     - **Установка поверх и удаление.** Установщик останавливает службу, заменяет файлы и
       запускает её снова; настройки и подписки сохраняются. Удаление спрашивает, стереть
       ли настройки и подписки, и убирает `C:\ProgramData\KVT` (списки, обновления zapret,
       журналы). Интернет после удаления работает — проверяется в чек-листе 5.7.
     - **Лицензии.** `LICENSE` (GPL-3.0) и `THIRD-PARTY-NOTICES`: Xray (MPL-2.0), sing-box
       (GPL-3.0), Wintun (лицензия на готовые бинарники), WinDivert (LGPL-3.0), zapret и
       Flowseal (MIT), flag-icons (MIT), Tauri (MIT / Apache-2.0). Раздел «О программе» в
       настройках: версии KVT, ядер и Flowseal, лицензии, ссылка на исходники.

       открытого проекта — проверить SignPath Foundation и Azure Trusted Signing.
     - **Несколько пользователей Windows.** Служба одна на компьютер. Предлагается: второй
       пользователь видит чужое подключение и может его отключить, но своё подключает
       только после этого.
   - **5.6 Автообновление.** GitHub Releases: `update-manifest.json` и подпись Ed25519
     (рабочий и запасной ключ, закрытые части у владельца). Хэш и размер архива берутся
     только из проверенного манифеста. Проверка не чаще раза в сутки через NetGovernor,
     установку выполняет служба, при сбое — откат на прежнюю версию.
     - **Защита манифеста.** Версия только растёт — откатить на старую уязвимую версию
       нельзя; у манифеста есть срок годности. Закрытых ключей нет в CI: CI собирает
       архив, владелец подписывает манифест у себя.
     - **Обновляется весь комплект одной версией:** kvt.exe, служба, ядра, Wintun, zapret.
       Служба не может заменить свой exe на ходу: она проверяет архив, запускает
       установщик и останавливается; новая версия после запуска проверяет себя, при сбое
       возвращается прежняя из резервной копии. Старое окно и новая служба сверяют
       `PROTOCOL_VERSION`: окно просит перезапуститься, а не показывает ошибки.
     - **Когда ставить.** VPN без спроса не обрывается: «Установить сейчас» или «При
       следующем отключении». Предупредить, что на время установки kill switch снимается
       вместе со службой.
     - **Откуда качать** — напрямую, при неудаче через туннель (как в 5.4).
   - **5.7 Подготовка релиза.** Последний шаг перед бетой.
     - **Автозапуск с Windows** свёрнутым в трей (включён после установки) и «Подключаться

6. Совместимость и защита канала — после беты. Принцип: не перегружать интерфейс — всё
   новое работает само или прячется в «Расширенных», главный экран не меняется. Порядок —
   по пользе и риску: подписки Happ и QR (много провайдеров, мало кода), затем
   WireGuard / AmneziaWG, последним — zapret для канала (нужно исследование).
   - **Подписки как у Happ.** Ссылки `happ://add`, `incy://add|import`, `v2raytun://import`
     разворачиваются в исходный HTTPS-URL. Заголовки `X-HWID` / `X-Device-*` с постоянным
     ID установки — только для подписок, где провайдер этого требует (переключатель
     у подписки). Закрытые `happ://crypt*` не расшифровываются. Обновление атомарное:
     ошибка или пустой ответ оставляет прежний список серверов.
   - **Импорт по QR-коду** из файла, буфера обмена или выделенной области экрана —
     в той же панели «+». Распознавание локальное, без сетевых запросов.
   - **WireGuard и AmneziaWG.** Вставка `.conf` целиком (Ctrl+V или «+»): несколько пиров,
     `PresharedKey`, IPv6-endpoint, параметры обфускации AWG; имя — из комментария `# …`.
     Только через sing-box в TUN; TCP-пинг для них не делается, сервер не считается
     недоступным. Риск, который решить до начала: проверить, есть ли в основной ветке
     sing-box параметры обфускации AWG. Если нет — форк ядра или amneziawg-go отдельным
     процессом; если ни то ни другое не годится — только WireGuard.
   - **Zapret для канала к серверу.** Третий вариант к «Гибриду» и «Zapret»: обход
     замедления самого соединения с VPN-сервером (TCP / QUIC / WireGuard), а не только
     YouTube и Discord. Стратегии под тип сервера, те же данные с белым списком флагов,
     автоподбор по факту подключения. Выключено по умолчанию; включается, когда
     «Почему не работает?» видит замедление канала — порог замедления хранится как данные
     в `presets/net-policy.json`. Хватит ли winws Flowseal или нужен winws2 — решить при
     реализации.
   - Экспорт диагностики перенесён в 5.4.
