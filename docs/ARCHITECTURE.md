# Архитектура KVT

## Процессы и привилегии

```
KVT.exe (обычные права)
├─ UI (Tauri/WebView2, выгружается в трей)
└─ kvt-core (Rust)
   ├─ подписки → модель → RoutingPlan → компилятор: Xray JSON | sing-box JSON | zapret2
   ├─ NetGovernor — все сетевые запросы приложения идут только через него
   ├─ тестер серверов, DNS-check, диагностика, детектор заморозки
   └─ HTTP: системный Schannel (отпечаток как у Windows/Edge), DoH
                 │ named pipe \\.\pipe\kvt-service (ACL + проверка подписи)
KVTService (SYSTEM, тонкая)
├─ запускает одно ядро с собственным TUN: xray.exe или sing-box.exe
├─ winws.exe (zapret Flowseal) — в режимах Zapret/Гибрид
└─ WFP: kill switch, запрет DNS мимо туннеля, IPv6, восстановление
```

Правила:

1. Недоверенные данные разбираются только в процессе без прав.
2. Служба не принимает путей, аргументов и сырых конфигов — только `ipc::Request`.
3. Секреты не попадают в argv, логи, WebView и аварийные дампы (`Secret`).
4. Локальных inbound в режиме TUN нет. Если порт неизбежен — пароль, случайный
   порт и WFP-фильтр по процессу.

## Ядра

| Возможность | Ядро |
|---|---|
| XHTTP, Finalmask, VLESS Encryption | только Xray |
| VLESS/REALITY/Vision, Trojan | Xray (по умолчанию) |
| Hysteria2, Shadowsocks, TUIC, AnyTLS, Naive | sing-box |

Оба ядра поднимают собственный TUN — цепочек через локальный SOCKS нет.
Выбор — `kvt_core::core_select::select_core`.

## RoutingPlan

Единый источник правды. Слои по приоритету: System (LAN, адреса серверов) → User →
Zapret → Preset (Россия) → Provider (выключен по умолчанию) → final.

Инварианты (`RoutingPlan::validate`, покрыты тестами):

- адрес VPN-сервера никогда не попадает под zapret и всегда в `--ipset-exclude`;
- правила подписки не могут включать zapret;
- zapret задаётся только доменами (hostlist).

## NetGovernor

Наблюдения сообщества (2026): ТСПУ замораживает узел примерно на 120 с, если к одному
SNI открыто больше ~3 TLS-соединений за короткое время; поток к подозрительным
подсетям замирает после ~16–20 КБ. Пороги не подтверждены официально и меняются,
поэтому хранятся как данные (`presets/net-policy.json`).

Политика по умолчанию: не больше 2 новых TLS на SNI за 60 с, пауза 2 с, после
заморозки — 180 с тишины, отпечаток не меняется.

## Проверка серверов

1. Статическая проверка (парсер).
2. DNS.
3. TCP/QUIC-доступность.
4. Рукопожатие через тестовое ядро без inbound.
5. Скачивание ~200 КБ.

Вердикт — `probe::classify`: работает / медленно / DNS / недоступен / заморозка
TLS / заморозка данных.

## Kill switch

Фильтры WFP в динамической сессии службы (`kvt-service/src/wfp.rs`). Разрешены: loopback,
интерфейс TUN, процессы ядра и службы, локальная сеть и DHCP; остальное блокируется на
уровнях ALE_AUTH_CONNECT v4/v6. Блокировка держится и после падения ядра — до «Отключить».
При падении или остановке службы Windows удаляет фильтры сама, поэтому KVT не может
оставить компьютер без интернета.

## Проверка утечек

`app/src-tauri/src/diagnostics.rs`: открытые SOCKS5 без пароля на локальных портах
(netstat + SOCKS5-приветствие), исходный адрес для IPv4/IPv6 (UDP connect без отправки
пакетов), резолвер через `whoami.akamai.net` — единственный сетевой запрос.

## Проверка DNS

`kvt_core::dns` — данные и выводы, `app/src-tauri/src/dnscheck.rs` — запросы. Пять резолверов
(Яндекс, Cloudflare, Google, Quad9, AdGuard) по UDP, DoT и DoH; около 30 коротких запросов,
по одному TLS-соединению на резолвер, повтор в течение минуты отдаёт прошлый результат.

- **Перехват**: `whoami.akamai.net` возвращает адрес резолвера, который на самом деле спросил
  Akamai. Перехват засчитывается, только если его подтверждает второй признак: ответ совпал
  с резолвером сети или DoH того же провайдера выходит из его сетей.
- **Подмена**: facebook.com и rutracker.org на разной инфраструктуре. Один адрес для обоих,
  адрес из частной сети или «нет такого домена» при ответе DoH — заглушка провайдера.
  Адреса 198.18.0.0/15 — FakeIP роутера (podkop, sing-box), это не подмена.
- DNS в конфиге ядра (`DnsPlan`) принимается службой только из каталога резолверов.

## «Почему не работает?»

`app/src-tauri/src/troubleshoot.rs`: сбор фактов (сеть, служба, подписка, TCP-пинг сервера,
интернет без VPN, одна проба через тестовое ядро с лимитами NetGovernor или запрос через
туннель) и чистая функция `conclude` — первый найденный сбой, понятный вывод и действие
одной кнопкой (подключить, отключить, переключиться на рабочий сервер, обновить подписку).

## Профили сетей и автопереключение

- Сеть узнаётся по MAC-адресу шлюза адаптера с маршрутом по умолчанию (`netinfo.rs`, IpHelper,
  без сетевых запросов, раз в 10 с). Профиль: включать/выключать VPN и какой режим ставить.
  «Включено» — это и VPN, и режим «Zapret». Работающее подключение перезапускается, если профиль
  меняет режим, если включён «Гибрид» (winws привязан к прежнему интерфейсу) или если для новой
  сети подобрана другая стратегия zapret.
- Проверка туннеля — `http://www.cloudflare.com/cdn-cgi/trace` (меньше 200 байт, страна выхода).
  Системное правило `with_health_check` ведёт этот домен через VPN в любом режиме.
- Автопереключение (`watchdog.rs`): проверка раз в минуту по открытому соединению, сбой
  подтверждается ещё двумя попытками, замена — по итогам полной проверки, затем по TCP-пингу;
  не больше трёх переключений за 30 минут. Если ни одна замена не заработала, выбор и подключение
  возвращаются на прежний сервер.
- При переподключении с kill switch прежние фильтры WFP держатся, пока не встанут новые.

## Этапы

1. ✅ kvt-core: подписки по сети, компиляторы конфигов, тестер с эмулятором ТСПУ.
2. ✅ Служба: ядра с TUN, списки podkop/runetfreedom, WFP kill switch, DACL на pipe,
   проверка клиента, проверка утечек, трей.
3. ✅ Проверка DNS, «Почему не работает?», профили сетей, автопереключение сервера.
3.1. ✅ Удобство списка серверов (как в Happ):
   - **Единый список.** На главной все подписки и ручные ключи идут группами в одном
     прокручиваемом списке; сервер выбирается из любой группы, без «Сделать основной».
     У группы: название, трафик, срок, «Обновить», «Пинг», свернуть/развернуть
     (состояние запоминается). Поиск — по всем группам.
   - **Выбор по ключу, а не по индексу.** `Choice.server_index` → `{подписка, ключ сервера}`,
     ключ — хэш адреса, порта, протокола и идентификатора. Выбор переживает обновление
     и перестановку серверов в подписке. Перенос старого `server_index` при запуске.
     Итоги проверок, трей и автопереключение (сначала та же подписка, потом остальные)
     работают с ключами.
   - **Кнопка «+»** в заголовке списка и в разделе «Подписки»: панель добавления
     ссылки или ключа поверх текущего списка; буфер обмена читается только по кнопке.
     Ключи без ссылки собираются в одну группу «Добавлено вручную».
   - **Флаги и эмодзи.** Windows не рисует эмодзи-флаги (вместо 🇩🇰 видно «DK»), поэтому
     пары региональных индикаторов в названии заменяются на SVG-флаги из встроенного
     набора flag-icons (MIT, без сетевых запросов). Остальные эмодзи — цветным шрифтом
     Segoe UI Emoji. Флаг стоит слева от названия, сам символ из названия убирается.
4. ✅ zapret Flowseal: режимы «Гибрид» и «Zapret», стратегии как данные с белым списком
   флагов, исключение VPN-серверов, автоподбор стратегии для сети, поиск конфликтов.
5. Всё, что нужно до первого релиза: журнал, аудит, миграция, надёжность, установщик,
   обновления. Порядок: 5.3 → 5.4 → 5.5 → 5.6 → 5.7 → бета 0.9.

   Шаг закрыт, когда тесты и clippy зелёные, документация обновлена, сделан коммит и
   пользователь проверил вживую от администратора всё, что идёт через службу. Пока живой
   проверки не было, у шага стоит пометка «вживую не проверено». Если изменилось то, что
   видит пользователь, в том же шаге обновляются README, частые вопросы и скриншоты.
   - ✅ **5.1 Журнал сетевых запросов.** *(вживую со службой не проверено)* Каждое
     соединение, которое открывает KVT или служба, записывается: время, кто (приложение /
     служба), зачем (подписка, проверка сервера, DNS, диагностика, zapret, списки,
     обновление), хост без пути и параметров, через что (напрямую / туннель / тестовое
     ядро), итог и длительность. Отказы NetGovernor тоже видны («отложено», «заморожено»).
     Только в памяти, последние 500 записей, на диск не пишется. Служба отдаёт свою часть
     по IPC. Раздел «Журнал»: сводка по хостам за час (соединения, пик в минуту,
     отложенные) и список запросов с фильтром — видно, что всплесков нет.
   - ✅ **5.2 Аудит ПК.** *(исправления через службу вживую не проверены)* Утечки мимо VPN
     (прокси WinINet/WinHTTP от других клиентов, IPv6 и Teredo, вручную прописанный DNS,
     DoH в браузерах), конфликтующий софт (другие VPN, адаптеры TAP/Wintun, драйверы
     WinDivert/GoodbyeDPI, антивирусы с перехватом HTTPS), остатки zapret (чужие службы
     winws/GoodbyeDPI, автозапуск .bat). Отчёт с кнопкой «Исправить» у каждого пункта;
     сам аудит ничего не меняет.
   - ✅ **5.3 Миграция.** *(на настоящих v2rayN, Throne, NekoRay и Hiddify не проверено — по исходникам и тестовым базам)* v2rayN, Happ, Hiddify, NekoRay / Throne: поиск в стандартных
     местах и «Указать папку». Данные чужих клиентов только читаются; переносятся
     подписки (по ссылке) и ключи, с предпросмотром перед импортом.
     Серверы из подписок не копируются — переносится сама подписка; если она сейчас не
     загружается, ссылка сохраняется и обновится позже. Базы SQLite читаются из копии.
     Happ хранит подписки зашифрованными — KVT только подсказывает скопировать ссылку.
     - **Как читать.** v2rayN 6+, Throne, Hiddify и Happ хранят данные в SQLite — база
       копируется, читается копия, так что работающий клиент не страдает. NekoRay и
       старый Throne — JSON в `config/profiles`. Записи превращаются в обычные ссылки и
       проходят тот же разбор, что и подписка; у каждого формата — тесты на образцах
       без настоящих ключей.
     - **Куда.** Подписки по ссылке — обычными группами, ссылки сразу шифруются DPAPI;
       серверы подписок по одному не переносятся — KVT загрузит их сам. Дубликаты (та же
       ссылка или тот же ключ сервера) пропускаются и видны в предпросмотре.
     - **Проверить перед закрытием шага:** что видит пользователь, если клиент найден, но
       база заблокирована или в неизвестном формате (понятное сообщение, а не пустой
       список).
   - ✅ **5.4 Надёжность и понятные сообщения.** *(вживую со службой не проверено: сон и
     гибернация, сеть со страницей входа, загрузки через туннель, правила ошибок ядер на
     настоящих сбоях)* Чинит то, что сломает первый релиз, и даёт журнал, без которого не
     отладить установщик на чистых машинах.
     - **Журнал на диске** (`kvt_core::diaglog`). Приложение —
       `%LOCALAPPDATA%\dev.kvt.client\logs\kvt.log`, служба —
       `C:\ProgramData\KVT\logs\service.log` (доступ только у SYSTEM и администраторов,
       приложение получает журнал по IPC `ServiceLog`). Ротация 2 × 1 МБ (`.1`), паника
       записывается хуком до `abort`. Каждая строка проходит маскировщик.
     - **Маскировщик** (`kvt_core::redact`): адреса серверов (множество, заполняется до
       запуска ядра: приложение — все серверы подписок, служба — адрес выбранного и его
       IP в фоне), у веб-ссылок только хост, ссылки на серверы целиком, UUID, токены от
       32 символов. Для конфигов ядер — по именам полей (`uuid`, `password`,
       `public_key`, `short_id`…). Строки ядра на диск — только узнанные правилом; у
       правил «только записать» (таймаут, DNS) — лишь код, раз в минуту: в таких строках
       бывают адреса сайтов пользователя.
     - **Экспорт диагностики.** Кнопка в «Почему не работает?» и на вкладке Zapret.
       Окно показывает каждый файл целиком (`README.txt`, `status.json`, `checks.json`,
       `config.json`, `kvt.log`, `service.log`, `core.log`, `netlog.json`); в zip
       сохраняется ровно показанное. Конфиг собирает приложение тем же компилятором и
       планом, что служба (`build_plan`).
     - **Настройки не теряются** (`settings.rs`). В `settings.json` — `version` и переносы
       по шагам (0 → 1: файл без версии). Битый JSON → копия `settings.bad.json`,
       настройки по умолчанию и сообщение в окне. Одно поле не того вида сбрасывается
       только оно: остальные (kill switch, профили сетей) читаются по одному.
     - **Тексты ошибок** (`errors.rs`). Отравленный замок, непонятный ответ службы, служба
       не запущена, разрыв pipe, ошибки reqwest и диска — по-русски и с действием;
       исходный текст — в журнал. `kvt-service --console` пользователю больше не
       советуется.
     - **Ошибки ядер — как данные** (`presets/core-errors.json`, `kvt_core::core_errors`):
       код, подстроки, текст, действие (`log` / `stop` / `reconnect`) и порог «N совпадений
       за окно», чтобы один неудачный запрос не останавливал VPN. `stop` останавливает ядро,
       но не kill switch (как при падении ядра); `reconnect` — один раз на подключение,
       второй случай останавливает. Если ядро упало само, причина берётся из правила.
     - **Честный статус** (`tunnel.rs`). После подключения — до трёх проверок туннеля; не
       прошло — на главной «Сайты не открываются» вместо «Подключено». Дальше состояние
       обновляет минутная проверка автопереключения — теперь она идёт при подключённом
       VPN всегда, даже если автопереключение выключено (один маленький запрос в минуту
       по открытому соединению).
     - **DNS с запасом — итог проверки.** Если основной DoH внутри туннеля не отвечает,
       Xray переходит на запасной DoH другого провайдера, тоже через туннель
       (`DnsPlan::reserve_doh`). Локальный резолвер помечен `skipFallback` и запасным не
       бывает. У sing-box перехода на запасной DNS нет — отказ DoH там виден как
       «Сайты не открываются», и «Почему не работает?» ведёт к проверке DNS. Системный
       DNS запасным не делаем: его запросы видел бы провайдер, а с kill switch он и не
       работает.
     - **Сон и пробуждение** (`power.rs`). `PowerRegisterSuspendResumeNotification`;
       через 5 с после `PBT_APMRESUMEAUTOMATIC` — проверка туннеля, не идёт —
       переподключение к тому же серверу и внеочередная проверка автопереключения.
     - **Сеть со страницей входа.** Служба (ей kill switch не мешает) запрашивает
       `http://1.1.1.1/cdn-cgi/trace` по IP, сокетом на адресе физического адаптера, мимо
       TUN (`kvt_core::captive`); перенаправление или чужая страница — сеть просит войти.
       Проверка — только когда данные через туннель не идут: автопереключение тогда не
       меняет сервер, а окно показывает «Отключить VPN»; «Почему не работает?» говорит то же.
     - **Удаление подписки при подключении.** Если выбранный сервер исчез из подписок
       (удалили подписку или провайдер убрал сервер при обновлении), VPN отключается и
       окно говорит об этом; к первому серверу другой подписки KVT не переподключается.
     - **Загрузки с GitHub.** `RoutingPlan::with_update_hosts` — точные имена
       (`Matcher::Domain`): `api.github.com`, `github.com`, `raw.githubusercontent.com`,
       `objects.` и `release-assets.githubusercontent.com` через VPN; остальной GitHub
       маршрутизируется как обычно. При подключённом VPN служба качает сначала напрямую
       (сокет на адресе физического адаптера), не вышло — через туннель; каждая попытка —
       в журнале запросов. Списки скачиваются до запуска ядра; если не обновились, а
       прежние на месте — повтор через туннель после подключения. Обновление Flowseal
       скачивается, пока VPN работает, и ставится уже после остановки winws.
   - **5.5 Установщик и подпись.** NSIS: KVT, служба, ядра, Wintun и комплект zapret в
     Program Files, регистрация службы. Удаление останавливает службу, снимает фильтры
     WFP и удаляет драйвер WinDivert. Подпись — шаг signtool в сборке, включается, когда
     есть сертификат; до этого служба проверяет клиента по пути и SHA-256 из манифеста
     установки, с подписью — ещё WinVerifyTrust и совпадение издателя.
     - **Что сейчас не так.** `npm run tauri build` уже собирает установщик с иконкой, но
       внутри только `kvt.exe`: без службы, ядер и zapret «Подключить» не работает. И
       ставит его по умолчанию в `%LOCALAPPDATA%`, куда пишет любая программа
       пользователя, — а служба доверяет `kvt.exe` из своей папки.
     - **Как собрать средствами Tauri.** `installMode: "perMachine"` — только
       `C:\Program Files\KVT`, один запрос прав администратора при установке.
       `bundle.resources` — `kvt-service.exe`, `cores\`, `zapret\`. `installerHooks`
       (`.nsh`): перед установкой и удалением остановить службу (иначе её файлы заняты),
       после установки — `kvt-service.exe install`, при удалении — `uninstall`. Мастер на
       русском, страница лицензии, свои картинки мастера; галочки «Ярлык на рабочем
       столе» и «Запустить KVT».
     - **Один файл.** Только NSIS (`setup.exe`), MSI убрать из `bundle.targets`: он нужен
       для корпоративной раскатки, а два установщика на странице релиза путают.
     - **Релиз собирает GitHub Actions по тегу** (`release.yml` рядом с `ci.yml`), не
       компьютер разработчика: чистая машина, исходники ровно из тега, ядра и zapret — по
       зафиксированным SHA-256 из `fetch-cores.ps1` и `fetch-zapret.ps1`. Аттестация
       происхождения (`actions/attest-build-provenance`): любой проверит командой
       `gh attestation verify`, что установщик собран из этого коммита. Для проекта без
       подписи это главный довод доверия, и SignPath Foundation подписывает только
       сборки из CI. Релиз создаётся черновиком с SHA-256 файлов в описании, публикует
       его разработчик после проверки. Локально то же делает `scripts\build-release.ps1`.
     - **Служба запускается сама.** Сейчас она `OnDemand`, а приложение её не запускает,
       поэтому после перезагрузки KVT не подключится. Тип запуска — «Автоматически
       (отложенный запуск)»; при сбое — перезапуск (до трёх раз); пользователям выдаётся
       право `SERVICE_START`, чтобы окно могло поднять остановленную службу без прав
       администратора.
     - **Первый запуск и «служба не отвечает».** Вместо ошибки на главной — объяснение и
       кнопка «Запустить службу».
     - **WebView2.** Загрузчик Evergreen в NSIS; отдельный офлайн-установщик со
       встроенным WebView2 для компьютеров без интернета.
     - **Удаление** спрашивает, стереть ли настройки и подписки, и убирает
       `C:\ProgramData\KVT` (списки, обновления zapret, журналы). Интернет после удаления
       работает — проверяется в чек-листе 5.7. Установка поверх прежней версии — в 5.6.
     - **Лицензии.** `LICENSE` (GPL-3.0) и `THIRD-PARTY-NOTICES`: Xray (MPL-2.0), sing-box
       (GPL-3.0), Wintun (лицензия на готовые бинарники), WinDivert (LGPL-3.0), zapret и
       Flowseal (MIT), flag-icons (MIT), Tauri (MIT / Apache-2.0). Раздел «О программе» в
       настройках: версии KVT, ядер и Flowseal, лицензии, ссылка на исходники.
     - **Пока нет подписи.** SmartScreen покажет «Система Windows защитила ваш
       компьютер» — инструкция на странице релиза. WinDivert заранее отправить в
       Microsoft Defender и Касперский как ложное срабатывание. Где взять подпись для
       открытого проекта — проверить SignPath Foundation и Azure Trusted Signing.
     - **Несколько пользователей Windows.** Служба одна на компьютер. Предлагается: второй
       пользователь видит чужое подключение и может его отключить, но своё подключает
       только после этого.
   - **5.6 Обновление вручную.** KVT сам ничего не скачивает и не устанавливает: новую
     версию пользователь берёт на странице GitHub Releases. Нет фоновых запросов, ключей
     подписи манифеста и установки силами службы — меньше того, что может сломаться или
     стать целью атаки.
     - **Два файла в релизе.** `KVT-x.y.z-setup.exe` — полная установка: KVT, служба,
       ядра, Wintun, комплект zapret, загрузчик WebView2. `KVT-x.y.z-update.exe` —
       обновление уже установленного KVT: kvt.exe и служба всегда, ядра, Wintun и zapret —
       только если они изменились. Обычно это несколько мегабайт вместо полного пакета.
       На странице релиза сказано, какой файл кому качать. Оба файла собирает
       `release.yml` (5.5) с аттестацией происхождения.
     - **От какой версии обновлять.** В обновление входят компоненты, изменившиеся с
       минимальной поддерживаемой версии (например, трёх последних релизов); эта версия
       записана в самом обновлении. Если KVT не установлен или старше минимума — сообщение
       «Скачайте полную установку» со ссылкой, ничего не меняется. Полный установщик
       поверх установленной версии тоже работает как обновление.
     - **Как ставится.** Закрыть окно KVT и предупредить, что VPN отключится на несколько
       секунд, а kill switch на это время снимается вместе со службой. Остановить службу,
       сохранить прежние файлы, заменить, запустить службу; не запустилась — вернуть
       прежние файлы. Настройки и подписки не трогаются, переносы схемы `settings.json`
       выполняет новая версия при запуске (5.4).
     - **Подлинность.** На странице релиза — SHA-256 обоих файлов; с сертификатом —
       подпись установщика и обновления. Манифест установки (5.5) обновляется вместе с
       файлами, чтобы служба принимала новый kvt.exe.
     - **Как узнать о новой версии.** В «О программе» — текущая версия и кнопка «Открыть
       страницу загрузки»: открывается браузер, сам KVT в сеть не ходит. Если GitHub не
       открывается напрямую, страницу можно открыть при включённом VPN.
     - **Окно и служба одной версии.** Обновление всегда меняет их вместе; если версии всё
       же разошлись (`PROTOCOL_VERSION`), окно просит переустановить KVT, а не показывает
       ошибки.
   - **5.7 Подготовка релиза.** Последний шаг перед бетой.
     - **Автозапуск с Windows** свёрнутым в трей (включён после установки) и «Подключаться
       при запуске» (выключено по умолчанию) — в «Настройках».
     - **Уведомления Windows**, пока окно закрыто: сервер заменён, соединение прервано,
       kill switch держит блокировку, zapret перестал справляться. Сейчас эти сообщения
       видны только в открытом окне. Без звука, отключаются в настройках.
     - **Сообщения в окне — через одно место.** Одинаковое сообщение не дублируется, а
       продлевается; на экране их не больше четырёх; то, что исчезает само, живёт по длине
       текста и не гаснет, пока над ним мышь или окно свёрнуто. Ошибки и предупреждения
       висят до «Понятно», как сейчас. Опыт zapret-kvn: их уведомления гасли до прочтения.
     - **Первый запуск** — три коротких шага поверх главной: добавить подписку или ключ →
       выбрать режим → подключить. Пропускается одной кнопкой, повторяется из настроек.
     - **Длинные списки.** Проверить главную на 2 000 и 10 000 серверов: сейчас рисуются
       все строки сразу. Если окно тормозит — рисовать только видимые строки.
     - **Значок в трее по состоянию**: подключено / отключено / ошибка, а не только
       подсказка при наведении.
     - **Ресурсы в фоне** (окно закрыто): kvt.exe — меньше 40 МБ памяти, процессор около
       нуля. Пересмотреть опросы (статус службы раз в 3 и 5 с, сеть раз в 10 с).
     - **README для пользователей**: установка, SmartScreen, антивирусы, частые вопросы;
       обновить статус проекта (сейчас там «этап 4 из 6»).
     - **Чек-лист релиза** (`docs/RELEASE-CHECKLIST.md`) и прогон на чистых виртуальных
       машинах Windows 10 22H2 и Windows 11 установщиком из черновика релиза, собранного в
       CI (5.5): установка → подписка → подключение → kill switch → обрыв → сон → смена
       сети → zapret → обновление с прошлой версии файлом обновления и полным установщиком
       поверх → удаление (интернет работает, служб и драйверов не осталось). Сюда же — все
       живые проверки, которые ещё не сделаны: 5.1, 5.2, 5.3 на настоящих клиентах, 5.4,
       профили сетей и автопереключение после полировки интерфейса (c089967).
     - **Бета 0.9** — небольшому кругу; новые версии — через страницу релизов (5.6).
       1.0 — после недели без серьёзных ошибок.
6. Совместимость и защита канала — после беты. Принцип: не перегружать интерфейс — всё
   новое работает само или прячется в «Расширенных», главный экран не меняется. Порядок —
   по пользе и риску: подписки Happ и QR (много провайдеров, мало кода), затем
   WireGuard / AmneziaWG, последним — zapret для канала (нужно исследование).
   - **Подписки как у Happ.** Ссылки `happ://add`, `incy://add|import`, `v2raytun://import`
     разворачиваются в исходный HTTPS-URL. Заголовки `X-HWID` / `X-Device-*` с постоянным
     ID установки — только для подписок, где провайдер этого требует (переключатель
     у подписки); провайдер может дать свой ранее зарегистрированный ID. Закрытые
     `happ://crypt*` не расшифровываются. Обновление атомарное: ошибка или пустой ответ
     оставляет прежний список серверов.
     - **У подписки в «Расширенных»:** фильтр серверов по названию (оставить / убрать),
       свой User-Agent и профиль клиента (Happ, INCY, v2RayTun) для провайдеров, которые
       отдают серверы только «своим» клиентам.
     - **HTTP-кэш** (`ETag` / `Last-Modified`): если подписка не изменилась, сервер
       отвечает коротким «не изменилось» — меньше трафика и меньше заметных запросов, в
       духе NetGovernor.
   - **Импорт по QR-коду** из файла, буфера обмена или выделенной области экрана —
     в той же панели «+». Распознавание локальное, без сетевых запросов.
   - **Флаг для серверов без эмодзи** — по локальной базе DB-IP Country Lite (CC BY 4.0,
     атрибуция в `THIRD-PARTY-NOTICES`), без сетевых запросов и без угадывания по
     словам в названии; у WireGuard — по адресу пира. База обновляется с выпуском KVT.
   - **Обновления Windows мимо VPN.** Системное правило маршрутизации: Windows Update,
     Defender и OneDrive идут напрямую — не тратят трафик VPN-подписки и не тормозят.
   - **Hysteria2 без потерь.** Проверить, что разбор ссылки и sing-box сохраняют
     `pinSHA256`, obfs (salamander), port hopping и ECH. Чего ядро не умеет — честное
     предупреждение при добавлении, а не молчаливое отбрасывание параметра. В zapret-kvn
     ради этого рядом с sing-box запускают официальный клиент Hysteria — так не делаем
     (см. «Чего не делаем»).
   - **WireGuard и AmneziaWG.** Вставка `.conf` целиком (Ctrl+V или «+»): несколько пиров,
     `PresharedKey`, IPv6-endpoint, параметры обфускации AWG; имя — из комментария `# …`.
     Только через sing-box в TUN; TCP-пинг для них не делается, сервер не считается
     недоступным. Риск, который решить до начала: проверить, есть ли в основной ветке
     sing-box параметры обфускации AWG. Если нет — форк ядра или amneziawg-go отдельным
     процессом; если ни то ни другое не годится — только WireGuard. zapret-kvn для AWG
     держит собственную сборку sing-box («sing-box extended») — риск подтверждается.
     - **Параметры AWG 1.5 и 2.0:** Jc, Jmin, Jmax, S1–S4, H1–H4, I1–I5, J1–J3, Itime.
     - **DNS у AWG.** Серверы Amnezia часто перехватывают порт 53 внутри туннеля: явно
       заданный частный DNS из `.conf` важнее, при публичном или пустом — шлюз туннеля.
       У обычного WireGuard порядок `DNS =` соблюдается как есть.
   - **Zapret для канала к серверу.** Третий вариант к «Гибриду» и «Zapret»: обход
     замедления самого соединения с VPN-сервером (TCP / QUIC / WireGuard), а не только
     YouTube и Discord. Стратегии под тип сервера, те же данные с белым списком флагов,
     автоподбор по факту подключения. Выключено по умолчанию; включается, когда
     «Почему не работает?» видит замедление канала — порог замедления хранится как данные
     в `presets/net-policy.json`. Опыт zapret-kvn, на который опираемся:
     - **winws2** с отдельным правилом на адрес выбранного сервера; адрес — свежим
       DNS-запросом перед подключением.
     - **Правила сразу на весь пул** серверов подписки, чтобы автопереключение не
       перезапускало winws2 и туннель.
     - **UDP-сервер без обхода получает правило «пропустить»**: обманные пакеты
       стратегии не должны попасть в туннель.
     - **Если winws2 упал**, пока подключение от него зависит, VPN отключается (или
       держит kill switch), а не работает без защиты канала.
     - Сами авторы пишут, что не все их стратегии справляются с замедлением VLESS, —
       шаг идёт последним и включается только после автоподбора с проверкой.
   - Экспорт диагностики перенесён в 5.4.
7. После 1.0 — только по отзывам пользователей. Список кандидатов, не обязательств;
   без команды не начинать.
   - Сервер «Авто»: лучший по итогам проверок, сам меняется при сбое.
   - **Переход с медленного сервера**, а не только с мёртвого. Уроки zapret-kvn: простой —
     не медленно (у них проверка сначала будила замеры 9–12 раз в час), поэтому
     подозрение — только когда трафик реально идёт и скорость ниже порога; затем
     контрольный замер текущего сервера; замена — если кандидат быстрее хотя бы вдвое;
     после замены пауза, покинутый сервер на полчаса не кандидат, не больше трёх замен
     в час, после ручного выбора — не трогать.
   - Трей: смена сервера и режима из меню.
   - На главной: время подключения, текущая скорость и небольшой график.
   - Трафик по программам: какая сколько скачала через VPN и напрямую.
   - Список серверов: избранное, своя страна у сервера, группировка по стране или
     протоколу, копирование ссылки, поиск по Ctrl+F.
   - Маршрутизация: значки сервисов и подсказка, какие домены входят в список.
   - Раздельное туннелирование по приложениям — только для sing-box (`process_name`), в
     Xray с TUN такого нет; решить, стоит ли оно сложности.
   - Английский интерфейс.
   - Перенос настроек на другой компьютер — без ключей или под паролем.

## Чего не делаем

Решения, к которым не возвращаемся без новой причины. Часть — по итогам разбора
zapret-kvn (2026-11-04): у них это есть, и это их слабые места.

- **Автообновление из приложения.** Новую версию пользователь скачивает сам (5.6).
- **Раздача VPN на другие устройства** (приставка, телевизор, телефон) через локальный
  прокси.
- **Telegram WS-прокси** — не перегружать KVT.
- **Окно с правами администратора.** Всё, что требует прав, делает служба; окно и разбор
  подписок работают с правами пользователя. У zapret-kvn всё приложение запускается от
  администратора — запрос UAC при каждом старте.
- **Локальный прокси без пароля**, тем более на `0.0.0.0`: через него любая программа на
  компьютере узнаёт адрес VPN-сервера. В режиме TUN локальных портов нет.
- **Два способа подключения на главной** (системный прокси и TUN с отдельными
  переключателями) и технические подробности на главном экране: порты, RTT, счётчики
  правил. Порты и задержки — во вкладках проверки и журнала.
- **Редактор сырого конфига ядра.** Маршрутизация — только через `RoutingPlan` с
  инвариантами; сгенерированный конфиг виден лишь в экспорте диагностики.
- **Несколько ядер в одном подключении** (ядро-помощник, отдельный клиент протокола
  рядом с основным) и свои патчи к ядрам. Исключение — крайняя необходимость (возможно,
  сборка sing-box ради AmneziaWG), и тогда версия закреплена.
- **Смесь языков в интерфейсе** («On», «Bootstrap DNS») и два элемента управления на
  одну настройку (список и переключатель у одного сервиса).
- **Реклама продавцов ключей** в приложении и README. Ошибки принимаются в открытых
  GitHub Issues, а не через скрытые формы и редиректы.
