# Архитектура KVT

## Процессы и привилегии

```
KVT.exe (обычные права)
├─ UI (Tauri/WebView2, выгружается в трей)
└─ kvt-core (Rust)
   ├─ подписки → модель → RoutingPlan → компилятор: Xray JSON | sing-box JSON | zapret2
   ├─ NetGovernor — все сетевые запросы приложения идут только через него
   ├─ тестер серверов, DNS-check, диагностика, детектор заморозки
   └─ HTTP: системный Schannel (отпечаток как у Windows/Edge), DoH
                 │ named pipe \\.\pipe\kvt-service (ACL + проверка подписи)
KVTService (SYSTEM, тонкая)
├─ запускает одно ядро с собственным TUN: xray.exe или sing-box.exe
├─ winws.exe (zapret Flowseal) — в режимах Zapret/Гибрид
└─ WFP: kill switch, запрет DNS мимо туннеля, IPv6, восстановление
```

Правила:

1. Недоверенные данные разбираются только в процессе без прав.
2. Служба не принимает путей, аргументов и сырых конфигов — только `ipc::Request`.
3. Секреты не попадают в argv, логи, WebView и аварийные дампы (`Secret`).
4. Локальных inbound в режиме TUN нет. Если порт неизбежен — пароль, случайный
   порт и WFP-фильтр по процессу.

## Ядра

| Возможность | Ядро |
|---|---|
| XHTTP, Finalmask, VLESS Encryption | только Xray |
| VLESS/REALITY/Vision, Trojan | Xray (по умолчанию) |
| Hysteria2, Shadowsocks, TUIC, AnyTLS, Naive | sing-box |

Оба ядра поднимают собственный TUN — цепочек через локальный SOCKS нет.
Выбор — `kvt_core::core_select::select_core`.

## RoutingPlan

Единый источник правды. Слои по приоритету: System (LAN, адреса серверов) → User →
Zapret → Preset (Россия) → Provider (выключен по умолчанию) → final.

Инварианты (`RoutingPlan::validate`, покрыты тестами):

- адрес VPN-сервера никогда не попадает под zapret и всегда в `--ipset-exclude`;
- правила подписки не могут включать zapret;
- zapret задаётся только доменами (hostlist).

## NetGovernor

Наблюдения сообщества (2026): ТСПУ замораживает узел примерно на 120 с, если к одному
SNI открыто больше ~3 TLS-соединений за короткое время; поток к подозрительным
подсетям замирает после ~16–20 КБ. Пороги не подтверждены официально и меняются,
поэтому хранятся как данные (`presets/net-policy.json`).

Политика по умолчанию: не больше 2 новых TLS на SNI за 60 с, пауза 2 с, после
заморозки — 180 с тишины, отпечаток не меняется.

## Проверка серверов

1. Статическая проверка (парсер).
2. DNS.
3. TCP/QUIC-доступность.
4. Рукопожатие через тестовое ядро без inbound.
5. Скачивание ~200 КБ.

Вердикт — `probe::classify`: работает / медленно / DNS / недоступен / заморозка
TLS / заморозка данных.

## Kill switch

Фильтры WFP в динамической сессии службы (`kvt-service/src/wfp.rs`). Разрешены: loopback,
интерфейс TUN, процессы ядра и службы, локальная сеть и DHCP; остальное блокируется на
уровнях ALE_AUTH_CONNECT v4/v6. Блокировка держится и после падения ядра — до «Отключить».
При падении или остановке службы Windows удаляет фильтры сама, поэтому KVT не может
оставить компьютер без интернета.

## Проверка утечек

`app/src-tauri/src/diagnostics.rs`: открытые SOCKS5 без пароля на локальных портах
(netstat + SOCKS5-приветствие), исходный адрес для IPv4/IPv6 (UDP connect без отправки
пакетов), резолвер через `whoami.akamai.net` — единственный сетевой запрос.

## Проверка DNS

`kvt_core::dns` — данные и выводы, `app/src-tauri/src/dnscheck.rs` — запросы. Пять резолверов
(Яндекс, Cloudflare, Google, Quad9, AdGuard) по UDP, DoT и DoH; около 30 коротких запросов,
по одному TLS-соединению на резолвер, повтор в течение минуты отдаёт прошлый результат.

- **Перехват**: `whoami.akamai.net` возвращает адрес резолвера, который на самом деле спросил
  Akamai. Перехват засчитывается, только если его подтверждает второй признак: ответ совпал
  с резолвером сети или DoH того же провайдера выходит из его сетей.
- **Подмена**: facebook.com и rutracker.org на разной инфраструктуре. Один адрес для обоих,
  адрес из частной сети или «нет такого домена» при ответе DoH — заглушка провайдера.
  Адреса 198.18.0.0/15 — FakeIP роутера (podkop, sing-box), это не подмена.
- DNS в конфиге ядра (`DnsPlan`) принимается службой только из каталога резолверов.

## «Почему не работает?»

`app/src-tauri/src/troubleshoot.rs`: сбор фактов (сеть, служба, подписка, TCP-пинг сервера,
интернет без VPN, одна проба через тестовое ядро с лимитами NetGovernor или запрос через
туннель) и чистая функция `conclude` — первый найденный сбой, понятный вывод и действие
одной кнопкой (подключить, отключить, переключиться на рабочий сервер, обновить подписку).

## Профили сетей и автопереключение

- Сеть узнаётся по MAC-адресу шлюза адаптера с маршрутом по умолчанию (`netinfo.rs`, IpHelper,
  без сетевых запросов, раз в 10 с). Профиль: включать/выключать VPN и какой режим ставить.
- Проверка туннеля — `http://www.cloudflare.com/cdn-cgi/trace` (меньше 200 байт, страна выхода).
  Системное правило `with_health_check` ведёт этот домен через VPN в любом режиме.
- Автопереключение (`watchdog.rs`): проверка раз в минуту по открытому соединению, сбой
  подтверждается ещё двумя попытками, замена — по итогам полной проверки, затем по TCP-пингу;
  не больше трёх переключений за 30 минут.
- При переподключении с kill switch прежние фильтры WFP держатся, пока не встанут новые.

## Этапы

1. ✅ kvt-core: подписки по сети, компиляторы конфигов, тестер с эмулятором ТСПУ.
2. ✅ Служба: ядра с TUN, списки podkop/runetfreedom, WFP kill switch, DACL на pipe,
   проверка клиента, проверка утечек, трей.
3. ✅ Проверка DNS, «Почему не работает?», профили сетей, автопереключение сервера.
3.1. ✅ Удобство списка серверов (как в Happ):
   - **Единый список.** На главной все подписки и ручные ключи идут группами в одном
     прокручиваемом списке; сервер выбирается из любой группы, без «Сделать основной».
     У группы: название, трафик, срок, «Обновить», «Пинг», свернуть/развернуть
     (состояние запоминается). Поиск — по всем группам.
   - **Выбор по ключу, а не по индексу.** `Choice.server_index` → `{подписка, ключ сервера}`,
     ключ — хэш адреса, порта, протокола и идентификатора. Выбор переживает обновление
     и перестановку серверов в подписке. Перенос старого `server_index` при запуске.
     Итоги проверок, трей и автопереключение (сначала та же подписка, потом остальные)
     работают с ключами.
   - **Кнопка «+»** в заголовке списка и в разделе «Подписки»: панель добавления
     ссылки или ключа поверх текущего списка; буфер обмена читается только по кнопке.
     Ключи без ссылки собираются в одну группу «Добавлено вручную».
   - **Флаги и эмодзи.** Windows не рисует эмодзи-флаги (вместо 🇩🇰 видно «DK»), поэтому
     пары региональных индикаторов в названии заменяются на SVG-флаги из встроенного
     набора flag-icons (MIT, без сетевых запросов). Остальные эмодзи — цветным шрифтом
     Segoe UI Emoji. Флаг стоит слева от названия, сам символ из названия убирается.
4. ✅ zapret Flowseal: режимы «Гибрид» и «Zapret», стратегии как данные с белым списком
   флагов, исключение VPN-серверов, автоподбор стратегии для сети, поиск конфликтов.
5. Миграция из других клиентов, журнал сетевых запросов, аудит ПК, подпись, автообновление.
   Обновления — по подписанному манифесту (Ed25519, рабочий и запасной ключ); хэш и размер
   архива берутся только из проверенного манифеста.
6. Совместимость и защита канала. Принцип: не перегружать интерфейс — всё новое работает
   само или прячется в «Расширенных», главный экран не меняется.
   - **Zapret для канала к серверу.** Третий вариант к «Гибриду» и «Zapret»: обход
     замедления самого соединения с VPN-сервером (TCP / QUIC / WireGuard), а не только
     YouTube и Discord. Стратегии под тип сервера, те же данные с белым списком флагов,
     автоподбор по факту подключения. Выключено по умолчанию; включается, когда
     «Почему не работает?» видит замедление канала. Хватит ли winws Flowseal или нужен
     winws2 — решить при реализации.
   - **WireGuard и AmneziaWG.** Вставка `.conf` целиком (Ctrl+V или «+»): несколько пиров,
     `PresharedKey`, IPv6-endpoint, параметры обфускации AWG; имя — из комментария `# …`.
     Только через sing-box в TUN; TCP-пинг для них не делается, сервер не считается
     недоступным.
   - **Подписки как у Happ.** Ссылки `happ://add`, `incy://add|import`, `v2raytun://import`
     разворачиваются в исходный HTTPS-URL. Заголовки `X-HWID` / `X-Device-*` с постоянным
     ID установки — только для подписок, где провайдер этого требует (переключатель
     у подписки). Закрытые `happ://crypt*` не расшифровываются. Обновление атомарное:
     ошибка или пустой ответ оставляет прежний список серверов.
   - **Импорт по QR-коду** из файла, буфера обмена или выделенной области экрана —
     в той же панели «+». Распознавание локальное, без сетевых запросов.
   - **Экспорт диагностики.** Одна кнопка в «Почему не работает?» и на вкладке Zapret:
     архив с итогами проверок, журналом службы и сгенерированными конфигами, где ключи,
     пароли, UUID и URL подписок скрыты. Перед сохранением показывается, что войдёт.
