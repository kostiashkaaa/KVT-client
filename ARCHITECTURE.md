# Архитектура KVT

Как устроен KVT и какие решения в нём приняты. Это описание для тех, кто читает код или
хочет помочь: что где лежит — в [CONTRIBUTING.md](CONTRIBUTING.md), как сообщить об
уязвимости — в [SECURITY.md](SECURITY.md). План по версиям ведётся отдельно; что вошло в
каждую — в [CHANGELOG.md](CHANGELOG.md).

*English summary:* the unprivileged app (`kvt.exe`) parses subscriptions and builds a
typed connection plan; a thin Windows service (SYSTEM) only accepts typed IPC requests,
builds the core config itself, runs one core with its own TUN plus zapret, and owns the
WFP kill switch. Secrets never reach the WebView, logs or diagnostics. Every network
request goes through a rate limiter (`NetGovernor`) and the request journal.

## Процессы и привилегии

```
KVT.exe (обычные права)
├─ UI (Tauri/WebView2, выгружается в трей)
└─ kvt-core (Rust)
   ├─ подписки → модель → RoutingPlan → компилятор: Xray JSON | sing-box JSON | zapret2
   ├─ NetGovernor — все сетевые запросы приложения идут только через него
   ├─ тестер серверов, DNS-check, диагностика, детектор заморозки
   └─ HTTP: системный Schannel (отпечаток как у Windows/Edge), DoH
                 │ named pipe \\.\pipe\kvt-service (ACL + путь и SHA-256 клиента)
KVTService (SYSTEM, тонкая)
├─ запускает одно ядро с собственным TUN: xray.exe или sing-box.exe
├─ winws.exe (zapret Flowseal) — в режимах Zapret/Гибрид
└─ WFP: kill switch, запрет DNS мимо туннеля, IPv6, восстановление
```

Правила:

1. Недоверенные данные разбираются только в процессе без прав.
2. Служба не принимает путей, аргументов и сырых конфигов — только `ipc::Request`.
3. Секреты не попадают в argv, логи, WebView и аварийные дампы (`Secret`).
4. Локальных inbound в режиме TUN нет. Если порт неизбежен — пароль, случайный
   порт и WFP-фильтр по процессу.

## Ядра

| Возможность | Ядро |
|---|---|
| XHTTP, Finalmask, VLESS Encryption | только Xray |
| VLESS/REALITY/Vision, Trojan | Xray (по умолчанию) |
| Hysteria2, Shadowsocks, TUIC, AnyTLS, Naive | sing-box |

Оба ядра поднимают собственный TUN — цепочек через локальный SOCKS нет.
Выбор — `kvt_core::core_select::select_core`.

## RoutingPlan

Единый источник правды. Слои по приоритету: System (LAN, адреса серверов) → User →
Zapret → Preset (Россия) → Provider (выключен по умолчанию) → final.

Инварианты (`RoutingPlan::validate`, покрыты тестами):

- адрес VPN-сервера никогда не попадает под zapret и всегда в `--ipset-exclude`;
- правила подписки не могут включать zapret;
- zapret задаётся только доменами (hostlist).

## NetGovernor

Наблюдения сообщества (2026): ТСПУ замораживает узел примерно на 120 с, если к одному
SNI открыто больше ~3 TLS-соединений за короткое время; поток к подозрительным
подсетям замирает после ~16–20 КБ. Пороги не подтверждены официально и меняются,
поэтому хранятся как данные (`presets/net-policy.json`).

Политика по умолчанию: не больше 2 новых TLS к одному серверу (пара SNI и адрес) за
60 с, пауза 2 с, после заморозки — 180 с тишины для всего SNI, отпечаток не меняется.

## Проверка серверов

1. Статическая проверка (парсер).
2. DNS.
3. TCP/QUIC-доступность.
4. Рукопожатие через тестовое ядро без inbound.
5. Скачивание ~200 КБ.

Вердикт — `probe::classify`: работает / медленно / DNS / недоступен / заморозка
TLS / заморозка данных.

При подключённом VPN проверка идёт с адреса физического адаптера
(`netinfo::physical_ipv4`): тестовое ядро — `sendThrough` / `inet4_bind_address`,
TCP-пинг — `tcp_ping_from`. Kill switch пропускает: тестовое ядро — тот же файл, что
разрешён фильтром.

## Kill switch

Фильтры WFP в динамической сессии службы (`kvt-service/src/wfp.rs`). Разрешены: loopback,
интерфейс TUN, оба ядра (тестовое ядро «Проверить» бывает не тем, что подключено) и
служба, локальная сеть (кроме портов DNS 53 и 853) и DHCP
(UDP 68→67, 546→547); остальное блокируется на уровнях ALE_AUTH_CONNECT и
ALE_AUTH_RECV_ACCEPT v4/v6 (входящие — без исключения для «System» в «Гибриде»: от его
имени принимают SMB и HTTP.sys). Внутри подслоя — веса: доверенное 15, блок DNS 10,
локальная сеть 5, остальное 0. Блокировка держится и после падения ядра — до «Отключить».

Падение службы: фильтры динамические и пропадают вместе с процессом, поэтому служба
пишет отметку `ProgramData\KVT\run\kill-switch.on`, пока kill switch включён, и при
старте (до pipe) восстанавливает kill switch без TUN (`restore_kill_switch`), если
отметка записана в эту загрузку Windows. Окну — `Failed { blocked: true }` с причиной
«служба перезапустилась после сбоя». Отметку стирают «Отключить», отмена и остановка
службы. Открытым интернет остаётся на время перезапуска службы (5 с у первого сбоя).

**DNS только через туннель** (`wfp::DnsGuard`), пока работает ядро, с kill switch и
без: Windows шлёт DNS во все интерфейсы сразу. Свой подслой: loopback, TUN, оба ядра и
служба — разрешены, остальное на 53 и 853 — блок; блок другого подслоя сильнее
разрешения локальной сети в kill switch. У sing-box то же делает `strict_route`, у Xray
аналога нет. Поэтому Xray резолвит имя сервера встроенным DNS через локальный резолвер
(`sockopt.domainStrategy` у выхода и у `downloadSettings`, имена — в `domains`
локального DNS), как sing-box (`default_domain_resolver`): системный DNS спрашивал бы
через сам туннель. Цена: имена из DNS роутера (принтер, NAS по имени) при VPN не
резолвятся — как и с sing-box раньше.

## Проверка утечек

`app/src-tauri/src/diagnostics.rs`: открытые SOCKS5 без пароля на локальных портах
(netstat + SOCKS5-приветствие), исходный адрес для IPv4/IPv6 (UDP connect без отправки
пакетов), резолвер через `whoami.akamai.net` — единственный сетевой запрос.

## Проверка DNS

`kvt_core::dns` — данные и выводы, `app/src-tauri/src/dnscheck.rs` — запросы. Пять резолверов
(Яндекс, Cloudflare, Google, Quad9, AdGuard) по UDP, DoT и DoH; около 30 коротких запросов,
по одному TLS-соединению на резолвер, повтор в течение минуты отдаёт прошлый результат.

- **Перехват**: `whoami.akamai.net` возвращает адрес резолвера, который на самом деле спросил
  Akamai. Перехват засчитывается, только если его подтверждает второй признак: ответ совпал
  с резолвером сети или DoH того же провайдера выходит из его сетей.
- **Подмена**: facebook.com и rutracker.org на разной инфраструктуре. Один адрес для обоих,
  адрес из частной сети или «нет такого домена» при ответе DoH — заглушка провайдера.
  Адреса 198.18.0.0/15 — FakeIP роутера (podkop, sing-box), это не подмена.
- DNS в конфиге ядра (`DnsPlan`) принимается службой только из каталога резолверов.

## «Почему не работает?»

`app/src-tauri/src/troubleshoot.rs`: сбор фактов (сеть, служба, подписка, TCP-пинг сервера,
интернет без VPN, одна проба через тестовое ядро с лимитами NetGovernor или запрос через
туннель) и чистая функция `conclude` — первый найденный сбой, понятный вывод и действие
одной кнопкой (подключить, отключить, переключиться на рабочий сервер, обновить подписку).

## Профили сетей и автопереключение

- Сеть узнаётся по MAC-адресу шлюза адаптера с маршрутом по умолчанию (`netinfo.rs`, IpHelper,
  без сетевых запросов, раз в 10 с). Профиль: включать/выключать VPN и какой режим ставить.
  «Включено» — это и VPN, и режим «Zapret». Работающее подключение перезапускается, если профиль
  меняет режим, если включён «Гибрид» (winws привязан к прежнему интерфейсу) или если для новой
  сети подобрана другая стратегия zapret.
- Проверка туннеля — `http://www.cloudflare.com/cdn-cgi/trace` (меньше 200 байт, страна выхода).
  Системное правило `with_health_check` ведёт этот домен через VPN в любом режиме.
- Автопереключение (`watchdog.rs`): проверка раз в минуту по открытому соединению, сбой
  подтверждается ещё двумя попытками (сбой проверки сразу после подключения уже подтверждён —
  перебор начинается сразу), замена — по итогам полной проверки и «данные шли» (сутки, переживают
  перезапуск, `outcomes.rs`), затем по TCP-пингу; не больше трёх переключений за 30 минут. Если ни одна замена не заработала, выбор и подключение
  возвращаются на прежний сервер.
- При переподключении с kill switch прежние фильтры WFP держатся, пока не встанут новые.

## Чего не делаем

Решения, к которым не возвращаемся без новой причины. Многие — по итогам разбора
похожих клиентов: у них это есть, и это их слабые места.

- **Окно с правами администратора.** Всё, что требует прав, делает служба; окно и разбор
  подписок работают с правами пользователя. Запроса UAC при каждом запуске нет.
- **Локальный прокси, тем более без пароля и на `0.0.0.0`**: через него любая программа
  на компьютере узнаёт адрес VPN-сервера. В режиме TUN локальных портов нет. Раздачи VPN
  на другие устройства через прокси тоже нет.
- **Редактор сырого конфига ядра.** Маршрутизация — только через `RoutingPlan` с
  инвариантами; сгенерированный конфиг виден лишь в экспорте диагностики.
- **Несколько ядер в одном подключении** и свои патчи к ядрам.
- **Компоненты из сети во время работы.** Ядра, winws, стратегии и списки zapret
  приходят только с выпуском KVT и со сверкой SHA-256. Автообновления тоже нет: KVT
  сообщает о новой версии, ставит её пользователь.
- **Трогать чужое.** Не убиваем процессы по имени и не меняем DNS сетевых адаптеров.
  Чужой VPN или zapret — только предупреждение и кнопка с согласия.
- **VPN и zapret по очереди.** «Гибрид» держит оба, адреса VPN-серверов исключены из
  перехвата winws.
- **Свои домены для zapret.** zapret обходит только блокировку по имени сайта; что не
  открывается — идёт через VPN по «Маршрутизации».
- **Интерфейс для энтузиастов** — десятки разделов и ручной подбор рецептов. У KVT три
  режима, автоподбор и ответ «почему не работает» простыми словами; мощные функции, если
  появятся, — в «Расширенных».
- **Реклама продавцов ключей** в приложении и README. Ошибки принимаются в открытых
  GitHub Issues.
- **Клиент для iOS.** Без российского App Store и платной подписи Network Extension не
  поставить, а ниша занята. Мобильная версия, если понадобится, — Android.
- **Оценка серверов по истории стабильности.** Замена при сбое — по факту: берётся
  сервер, через который данные идут сейчас.
