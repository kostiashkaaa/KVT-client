# Безопасность

KVT отвечает за то, куда уходит ваш трафик, поэтому к уязвимостям мы относимся серьёзно.

## Как сообщить об уязвимости

Пожалуйста, **не открывайте публичный Issue**. Сообщите приватно через
[Security Advisories](https://github.com/kostiashkaaa/KVT-client/security/advisories/new)
этого репозитория («Report a vulnerability»).

Опишите, что можно сделать и как это воспроизвести, и укажите версию KVT и Windows.
Не прикладывайте свои настоящие ключи и ссылки подписок.

Мы ответим, как только разберёмся, и выпустим исправление новой версией на странице
[Releases](https://github.com/kostiashkaaa/KVT-client/releases). Если хотите, укажем вас
в описании исправления.

## Что особенно важно

- утечки трафика или DNS мимо туннеля, в том числе при обрыве и с включённым kill switch;
- способы управлять службой KVT (у неё права администратора) из чужой программы;
- утечка ключей, ссылок подписок или адресов серверов в журналы, диагностику или окно;
- разбор подписок и ссылок, после которого KVT падает или делает лишнее.

## Модель угроз

Что KVT защищает, от кого и где проходят границы доверия. Устройство подробнее — в
[ARCHITECTURE.md](ARCHITECTURE.md).

**Что защищаем:** трафик и DNS — не уходят мимо туннеля, пока VPN включён (с kill
switch — и пока он переподключается или упал); секреты — ключи серверов, ссылки
подписок с токенами, адреса серверов; систему — служба работает от SYSTEM, и через неё
нельзя получить эти права.

**Границы доверия:**

| Граница | Что проверяется |
|---|---|
| Окно (`kvt.exe`, права пользователя) → служба (SYSTEM) | named pipe только для SYSTEM, администраторов и интерактивных пользователей, только локально; клиент — `kvt.exe` из каталога службы, у установленной службы его SHA-256 сверяется с манифестом в `ProgramData\KVT` (нет манифеста — отказ); пока VPN, zapret или kill switch работают, команды принимаются только от пользователя Windows, который их включил, или от администратора (`access.rs`), остальным — статус и сведения о zapret; только типизированные команды `kvt_core::ipc`, без путей, аргументов и сырых конфигов — конфиг ядра служба строит сама |
| Провайдер подписки → KVT | подписка разбирается только в окне, без прав; служба заново проверяет пришедший сервер; ответ ограничен по размеру, ID устройства при перенаправлении на другой хост не отправляется |
| Ядро (Xray, sing-box, sing-box для AmneziaWG, winws) | приходят только с выпуском KVT, со сверкой SHA-256; работают в Job Object службы; ядро AmneziaWG (форк sing-box-lx, один сопровождающий) запускается только для серверов AmneziaWG — остальные идут на ядра без форка; из `.conf` берутся только ключи, адреса и параметры обфускации по белому списку, команды `PostUp`/`PreUp` не выполняются; конфиг с секретами лежит на диске до старта ядра в каталоге только для SYSTEM и администраторов |
| Диск | ссылки подписок и ключи — DPAPI текущего пользователя; каталоги службы в `ProgramData\KVT` — только SYSTEM и администраторы, каталог с чужим владельцем убирается в сторону и создаётся заново |
| Журналы, диагностика, окно | ключи, токены, UUID и адреса серверов маскируются (`kvt_core::redact`); в WebView уходят только данные для показа |

**От кого защищаемся:** другая программа или другой пользователь на том же компьютере
без прав администратора; провайдер подписки с враждебным ответом; провайдер интернета,
который подменяет DNS, режет и замораживает соединения.

**Вне модели:** администратор компьютера и вредоносная программа с его правами —
они могут заменить службу; программа, запущенная от вашего же имени, может читать
то, что расшифровывает DPAPI (ссылки подписок); взлом самого VPN-сервера; анализ
трафика по объёму и времени. Подписи кода пока нет: сверка с манифестом защищает от
подмены `kvt.exe` без прав администратора, но не заменяет подпись. Владелец сеанса
помнится только в памяти: после перезапуска службы (сбой при включённом kill switch)
«Отключить» снова может любой вошедший пользователь.

**Что смотреть первым при аудите:**

1. `crates/kvt-service/src/pipe.rs`, `access.rs`, `handler.rs`, `manifest.rs` — кто может управлять
   службой и какие команды она принимает.
2. `crates/kvt-service/src/wfp/`, `supervisor/killswitch.rs` — kill switch и DNS
   только через туннель, восстановление после падения службы.
3. `crates/kvt-service/src/dirs.rs`, `win.rs` — права на каталоги и подмена файлов.
4. `crates/kvt-core/src/parser/`, `subscription.rs`, `compile/` — разбор недоверенных
   подписок и сборка конфига ядра (никаких параметров ядра «как есть» из ссылки).
5. `crates/kvt-core/src/redact.rs`, `netlog.rs` — что попадает в журналы.

## Поддерживаемые версии

Исправления выходят для последней версии. Обновиться можно файлом
`KVT-x.y.z-update.exe` со страницы Releases.

---

**English:** please report vulnerabilities privately via
[Security Advisories](https://github.com/kostiashkaaa/KVT-client/security/advisories/new),
not in public issues. Fixes ship in the latest release. The threat model above: the
unprivileged app talks to the SYSTEM service over a local named pipe that only accepts
`kvt.exe` from the service folder (hash-checked against the install manifest) and only
typed commands; untrusted subscriptions are parsed without privileges; cores ship with
KVT and are hash-checked; secrets are DPAPI-encrypted and redacted from logs. Out of
scope: a local administrator, malware running as you, a compromised VPN server.
